The one mistake worth avoiding

Flash the .bin in 2-flash-the-board. Do not download overwatch-fw.bin from the releases page and flash that.

They look interchangeable. The file here holds the bootloader and the program. The one on the releases page is the program alone — meant for a board that already works, updating itself. Flash the wrong one and the board stays dark with no error, looking exactly like a bad solder joint.

2Flash the board

If you are using a separate ESP32 and panel rather than an all-in-one CYD, wire it first — wiring-discrete-esp32-only.md. On a CYD there is nothing to wire.

SDO / MISO stays disconnected

It would land on GPIO 12, which the ESP32 reads at power-on to choose its flash voltage. A wire there stops the board booting at all — and it is the last thing you would suspect, because the module's silkscreen invites you to fit it.

Plug the board in over USB, then, from inside that folder:

overwatch flash --image overwatch-@VERSION@.bin

It finds the board, stops the daemon so the serial port is free, writes the image and verifies what it wrote. A minute or two, and the screen stays dark the whole time — that is normal. Do not unplug it.

The board reboots by itself and should light up. If it stays dark, esptool has already verified the firmware, so the flash is not the problem — check the wiring and the panel.

Only for a unit that should boot to the Codex mark instead of the Overwatch one:

overwatch provision --edition codex

3Hand it over

Everything from here happens on your friend's computer. They need Claude Code 2.1.100 or newer. One line in a terminal — the four platforms are in install-commands.txt, and INSTALL-CARD.pdf is the page to hand over with the unit.

curl -fsSL https://github.com/SleepyUnicon/Overwatch/releases/latest/download/overwatch-macos-arm64.tar.gz | tar xz && ./overwatch/overwatch
Tell them to paste the command, not click a download link

macOS quarantines browser downloads and refuses to run them — "cannot be opened because the developer cannot be verified". curl sets no such flag. This is the single most likely thing to go wrong at handover.

Then they plug the board in. It finds itself, the setup screen steps aside as soon as the software says hello, and the board keeps itself updated from then on. No account, no WiFi, no cloud.

4Check it before it leaves

overwatch status
Bridge      running (launchd, pid N)
App         @VERSION@
Board       /dev/cu.usbserial-XXXX -- id XXXXXXXX, firmware @VERSION@
Claude Code 2.1.238

App and Board must show the same version. They ship from one tag, so a mismatch means one half is stale.

5Keeping their unit stable while yours is not

Boards check /releases/latest/, and GitHub's "latest" deliberately skips pre-releases. So you can experiment freely on your own unit:

You wantCommand
Everyone gets itbash tools/release.sh
Only your test bedOVERWATCH_PRERELEASE=1 bash tools/release.sh
then put it on your own board by cable: python3 tools/package_firmware.py && overwatch flash
Promote one latergh release edit vX.Y.Z --prerelease=false

Nothing reaches a friend's board until you cut a normal release.
